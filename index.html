Source CCV Selection & Deduplication (OnRamp._mergeCCVLists)

Every cross-chain message collects verifiers from four layers: user-requested CCVs (with address(0) as the "include defaults" sentinel), token pool requirements (IPoolV2.getRequiredCCVs), lane defaults, and non-overridable lane-mandated CCVs.

  • Token-only exception: Pure token transfers (no receiver data, gasLimit = 0) skip default CCVs unless the user explicitly passes address(0)—using only pool-required + lane-mandated CCVs (INV-SRC-4 / INV-SRC-6).
  • Custom ccvArgs precedence: If a user manually specifies a lane-mandated CCV with custom ccvArgs, deduplication keeps the user entry's args (INV-SRC-10).

Phase 1: Commit Plugin (commit/plugin.go)

Observes finalized source-chain messages, generates per-source Merkle roots, queries the RMN network directly off-chain so RMN signatures ride inside the initial CommitReport, and attaches gas/token price snapshots for billing.

Phase 2: Execute Plugin (execute/plugin.go)

Multi-round Role DON pipeline: (1) Destination readers scan pending CommitReports, (2) Source readers fetch matching payloads, (3) Destination readers compute merklemulti proofs and execution order, then submit to OffRamp.execute.

1. Strict Order of Effects

INV-DST-1 / 2: CCV quorum passes before any token release (releaseOrMint), and token release finishes before calling ccipReceive.

2. Out-of-Order & Replay Safety

INV-EXEC-2 / 4 / 6: Execution is permissionless and unordered; SUCCESS is final, while FAILED messages may be retried without double-minting.

3. Gas-Buffer Isolation

_callWithGasBuffer reserves safe gas to record failure states cleanly if an untrusted CCIPReceiver burns all forwarded gas.
